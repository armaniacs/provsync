# セキュリティ

## 秘密の扱い(設計)

provsync が中継するのは `apiKeyEnv`(環境変数名)だけ。実キーの値はどこにも出ない。pull のときに秘密情報らしいフィールドを検出すると、警告を出したうえでそのフィールドを落とす。push では逆に、対象ツール設定にすでに存在する秘密フィールドをそのまま保持する。削除も、セントラル設定への持ち出しもしない。

秘密フィールドの判定基準と、各コマンドでの挙動の詳細は[使い方の「秘密情報の扱い」](usage.md#秘密情報の扱い)を参照。diff の出力は既定で実値を `********` に伏せる(表示上のマスクで、書き込まれるファイルの内容には影響しない)。

なお、バックアップには書き込み前のファイルの内容が保存される。ファイル内の秘密はここに残りうる。

## 通信の範囲

通信するのは `provsync check` だけ(各 provider の API 到達可否確認)。他のコマンドは同期対象の設定ファイルと状態ディレクトリ以外にアクセスしない。

## 脆弱性の報告

脆弱性を見つけた場合は、公開の Issue に書かず、GitHub の「Report a vulnerability」(Security タブ > Advisories)から非公開で報告してください。

- 報告には、再現手順、影響を受けるバージョン、想定される影響を含める。実際の API キーなどの秘密は含めない。
- 受領の確認は 7 日以内を目安とする。
- 修正は最新のマイナーバージョン系列のみを対象とする。
- 修正版のリリース後に、報告者の同意を得て内容を公開する。

## 対象範囲

次のものは報告の対象です。

- 秘密(`apiKey`、`token` など)が、出力・ログ・セントラル設定・バックアップ以外の場所へ書かれる、または意図せず表示される問題
- バックアップや状態ディレクトリの権限に起因する情報漏えい
- 設定ファイルの破損や、意図しないファイルの上書きにつながる問題
