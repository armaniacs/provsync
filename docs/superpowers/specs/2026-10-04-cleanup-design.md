# provsync 完全クリーンアップ 設計

日付: 2026-10-04

## 目的

provsync が管理するファイル（セントラル設定・状態・バックアップ・履歴）を完全に削除する手段を提供する。macOS ではゴミ箱へ移動し、ゴミ箱が無い環境では直接削除する。

## スコープ

- 新規サブコマンド `provsync cleanup` を追加する。dispatch・ヘルプ・補完は既存の `commandRegistry` から自動生成する。
- 削除対象は provsync 管理分のみに固定する:
  - セントラル設定（`~/.config/provsync/config.json`）
  - 状態ディレクトリ全体（`~/.local/state/provsync/`：履歴・バックアップ・ロック）
- ツール設定ファイル（kilo.json・opencode.jsonc 等）とバイナリは一切触らない。ツール設定は他アプリが管理するユーザーデータのため。
- TUI メニューに `cleanup` 項目を追加する。

## 非目標(YAGNI)

- ツール設定・バイナリの削除。
- Linux の freedesktop Trash 対応（直接削除でよい）。
- 外部 trash ライブラリの導入（`go.mod` の stdlib-only 方針を維持）。
- 削除の undo（ゴミ箱自体が macOS での復元手段）。

## アーキテクチャ

- `internal/cli/cleanup.go`（新規）に `cmdCleanup` を置く。1ファイル1責務の規約に従う。
- Trash 移動は非公開ヘルパーに切り出す（`internal/cli` 内または `fsutil`）。子プロセス呼び出しはここに限定する。
- macOS 判定は `runtime.GOOS == "darwin"` で行う（既存の `cli.Supported` とは独立）。

## CLI 仕様

```
provsync cleanup [--write] [--yes]
```

1. フラグなし → 対象一覧と合計サイズのプレビュー表示のみ。終了コード 0。
2. `--write` → プレビュー表示 → `本当に削除しますか? y / n` の必須確認 → `y` のみ実行（`n`/空は中止）。非端末 stdin では実行不可エラー（終了コード 1）。
3. `--yes` → プレビュー表示 + 確認スキップで実行（`--write` 不要）。TUI・スクリプト用。apt の `-y` と同じ流儀。
4. 実行時は状態ディレクトリの排他ロックを先に取得する（取得失敗時はエラー終了）。
5. 削除順は状態ディレクトリ → セントラル設定の順。各対象の成否を表示する。

## Trash 仕様

- macOS: `osascript -e 'tell application "Finder" to delete POSIX file "..."'` でゴミ箱へ移動する。Trash 内の同名衝突は Finder の自動リネームに任せる。
- macOS 以外: `os.RemoveAll` で直接削除する。
- osascript 失敗時は警告を出して直接削除にフォールバックする（削除自体が主目的のため）。

## TUI 仕様

- メニューに `cleanup` 項目を追加する（引数なし・プロンプトなし）。説明文は CLI と同じカタログ（`usage.summary.cleanup`）を流用する。
- 選択すると対象プレビューを表示し、確認画面が警告を兼ねる。`y` で `cleanup --yes` を実行する（ユーザーは `--write` を意識しない）。結果画面に成否を表示する。
- プレビュー失敗時は適用抑止＋戻り誘導の既存仕様に従う。

## エラーハンドリング

- osascript 失敗 → 警告 + 直接削除フォールバック。
- 非端末 stdin での `--write`（`--yes` なし）→ 実行不可エラー（終了コード 1）。
- ロック取得失敗 → エラー終了（既存コマンドと同一挙動）。
- 部分失敗時は対象ごとの成否を表示し、終了コード 1 で残存ファイルを明示する。

## テスト戦略

- 単体：プレビュー内容（対象・サイズ表示）、`--write` / `--yes` の組み合わせ動作、ロック競合時の拒否。osascript 呼び出し部は差し替え可能にしてフォールバックを検証する。
- TUI：メニュー遷移、プレビュー→確認→`cleanup --yes` の引数固定（スタブ検証）。新規 i18n キーは日英両カタログに追加し、既存のカタログ完全性テストで parity を検出する。
- 実機確認（ユーザー作業）：macOS 実機でゴミ箱への移動を確認する手動 QA を DoD に含める。

## i18n

- 新規ユーザー向け文言は `internal/i18n` の日英両カタログに追加する。en を正とし、ja を追加言語とする既存規約に従う。
- `status` 結果画面の `i` 作成フローと同様、TUI 内の文言はカタログ経由のみとする。
