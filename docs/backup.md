# バックアップと undo

## 仕組み

書き込みの直前には、影響する全ファイルが 1 操作としてバックアップされる。保存先は `~/.local/state/provsync/` で、操作履歴の `index.json` と、SHA-256 検証付きのファイルスナップショットを置く `backups/<op-id>/` からなる。

履歴は最新 20 操作を保持し、古いものから自動で削除される。保持数は `PROVSYNC_KEEP` 環境変数で変更できる(1 以上の整数)。

## 履歴の表示

```console
$ provsync undo --list
20261002T093045-8c2d  2026-10-02 09:30:45  push opencode
    /home/you/.config/opencode/opencode.json
20261002T093012-3fa1  2026-10-02 09:30:12  pull kilocode
    /home/you/.config/provsync/config.json
```

## 復元

引数なしの `provsync undo` が直前の書き込みを、`provsync undo <id>` が指定した操作を復元する。undo は直接適用されるため、`--write` は要らない。復元前の現状は新しい操作として記録され、やり直し用の ID が表示される(`やり直し: provsync undo <id>`)。

履歴をまとめて掃除したいときは `provsync undo --prune --keep <n>` を使う。新しい n 件を残して残りを削除し、削除件数が表示される。

## --no-backup の挙動

`--no-backup` での書き込みはマーカー操作として履歴に記録される。後続の `undo` では「直近の書き込みはバックアップなしで行われたため、この undo はそれより前の状態に戻します」と警告される。

## 権限

- 新規作成されるセントラル設定と状態ディレクトリは 0600 / 0700 で作られる。既存ファイルの権限は変更されない。
- `status` は権限が緩い場合に `chmod` を案内する。

## シンボリックリンク

- dotfiles 管理のシンボリックリンクは維持される。書き込みはリンク先の実体に対して行われ、リンク自体が通常ファイルに置き換わることはない。
- リンク切れは書き込み前にエラーになる。`list` はリンク先を ` (symlink → 実体)` で表示する。

## 排他ロック

書き込みと undo の復元区間は、状態ディレクトリの排他ロック(flock)で保護される。同じ状態ディレクトリに対する並行実行は後発が待機し、10 秒でタイムアウトして「別の provsync が実行中」で終了する。プレビュー・`diff`・`status` はロックを取らない。

ロックは flock なので、プロセスが異常終了しても OS が解放する。手動での後始末は要らない。
