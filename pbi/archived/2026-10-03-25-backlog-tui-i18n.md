# PBI: tui ダッシュボードの i18n 化（ja/en・backlog）

## ユーザーストーリー
日本語を読めない provsync-tui の利用者として、tui の表示・エラー・ヘルプを自分の言語（英語）で読みたい、なぜなら CLI とドキュメントサイトは日英対応済みなのに tui だけ日本語固定で、体験が分断されているから

## 背景
- tui は独立 Go モジュール（`tui/go.mod`、bubbletea + golang.org/x/term、`provsync-tui` バイナリ）であり、親モジュールの `internal/i18n` を直接 import できない
- 日本語文字列は約 15 件（`tui/main.go` × 3、`tui/model.go` × 3、`tui/tui.go` × 約 12・View は `+` 連結中心）
- `tui/model.go` は `statusReport` スキーマを `internal/cli` と重複定義しており、drift 行の逆解析フォールバック（`strings.Index(line, ": ")`）が ja ラベル形式に依存する
- PBI 2026-10-03-24（CLI i18n）の深掘りで、JSON 値（drift / warnings）がロケール連動に決定した。tui は子プロセスで `provsync status --json` を実行するため、tui 端末の LANG が en だと drift 行が英語になる。tui 側は DriftEntries（言語中立）を優先するため緩和済みだが、本 PBI で確認・整理する

## 改善案
- tui/go.mod に親モジュールへの `replace` 指令を追加し、`internal/i18n` を共用する（推奨）
- 代替: tui 内に最小カタログを複製（モジュール境界を壊さないが二重管理になる）
- drift 行の逆解析は DriftEntries 優先に統一し、文字列逆解析フォールバックを削除または機械値ベースに変える

## 制約
- 親モジュールの `internal/i18n` カタログ（ja が正・完全性テストあり）に en を追加する形で重複を持たない
- `go.mod` への外部依存追加は不要（replace は既存 2 モジュール間の解決のみ）
- `make check` / tui モジュールのテストがパスすること

## BDD受け入れシナリオ

Scenario: 英語ロケールで tui を起動すると英語で表示される
  Given PROVSYNC_LANG=en の環境で provsync-tui を起動する
  Then  表示・ヘルプ・エラーがすべて英語で表示される

Scenario: 未対応ロケールで tui を起動すると日本語で動く
  Given PROVSYNC_LANG=fr の環境
  When  provsync-tui を起動する
  Then  メッセージは日本語で表示され、エラーにならない

Scenario: 非対話端末でのエラーが英語になる
  Given PROVSYNC_LANG=en の環境で標準入力が端末でない
  When  provsync-tui を起動する
  Then  `provsync-tui: ` 接頭辞のエラーが英語で出力される

## 受け入れ基準

## テスト戦略
- 単体: i18n カタログの完全性テストに tui 用 ID が含まれること
- 統合: 非対話端末での起動エラー（ja / en）、子プロセス呼び出しのロケール伝播
- tui モジュール内テスト: model.go の statusReport パース（DriftEntries 優先）
